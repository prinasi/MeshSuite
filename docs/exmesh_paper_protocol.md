# ExMesh DTU 论文参数复现与白背景修正

当前默认命令为：

```bash
conda activate msbench
./single_train.sh exmesh dtu/scan24 0
./single_train.sh exmesh dtu/all 0
```

最后的参数是 GPU 编号。第二条依次运行论文中的 15 个场景；本轮完整实测仅 scan24。
已有结果默认跳过，重新训练 ExMesh 可加 `--retrain`，经校验的独立初始化仍会复用。
需重新生成初始化时，先将对应初始化目录移至独立备份目录。

## 背景修正

按用户要求，默认 DTU 路径统一采用白色背景。
原生 ExMesh 训练一直读取 RGBA alpha 作为轮廓，但此前配置 `white_background=false`，
将透明区域合成黑色。这不是未读取 alpha，而是背景配置与本次要求不符。

还发现官方 2DGS 的 COLMAP 路径直接使用 RGB 监督，不将 alpha 合成进 RGB；
所以仅传 `--white_background` 不足以保证透明像素的 RGB 正确。本轮同时：

1. 分通道缩放 RGBA，将 RGB 按 `alpha * RGB + (1 - alpha) * white` 合成一次。
2. 保留原 alpha 通道，供 TSDF 的前景深度过滤使用。
3. 以 `--white_background` 从头训练新的 2DGS 初始化，使用独立缓存。
4. ExMesh 从原始 RGBA 同样合成一次白背景，并保留 alpha 作轮廓监督。
5. 图像评测启用白背景 alpha 合成；渲染配置与检查点均记录 `[1, 1, 1]` 背景。

还修复了通用 DTU 配置逻辑：此前 `full` 模式会无条件覆盖适配器为黑背景，
现在尊重显式的数据集/训练背景。真实最终模型的原始 CUDA 输出已检查：214250 个
完全未覆盖像素全部为纯白。公共图像/视频路径还会按数据集元数据重新合成背景，
所以本轮修复覆盖逻辑前后的图像指标相同；不能将此前原始适配器为黑色等同于最终公共图像也是黑色。

全部 49 个视图的预处理 RGB 已逐像素核对、alpha 已逐项核对，原始数据未改动。
最终实际 CUDA 渲染也核查了完全未覆盖像素为纯白。没有仅通过重渲染旧模型替代重新训练。

## 固定设置与仍存在的复现边界

依据[论文 §4.1、表 1、表 6](https://arxiv.org/html/2606.07288)：

| 项目 | 本轮设置 |
| --- | --- |
| 初始化 | 2DGS 7000 步，TSDF 分辨率参数 256 |
| ExMesh | 8000 步；1000 步预热，1000–7000 每 500 步拓扑更新，最后 1000 步冻结 |
| 图像、背景、视图 | 800×600、白背景 alpha 合成、全部 49 个训练视图 |
| 深度 / 平滑 / 偏移权重 | 0.01 / 1000 / 1000 |
| D-SSIM / 轮廓权重 | 0.2 / 0.005 |
| 顶点 / 纹理学习率 | 0.0005 / 0.0025 |
| 纹理分辨率 | 2560×2560 |
| 官方 2DGS 版本 | `f3e3b9fa67bbd1c75e05167ff37391d8dab2a678` |
| 2DGS DTU 补充设置 | lambda_dist=1000、depth_ratio=1、seed=0、num_cluster=1 |

用户此前确认：未公开的初始化细节采用固定官方 2DGS DTU 建议；算法细节保留作者发布代码。
因此，主要参数对齐不等于已证实与作者产生表格结果的完整实验一致：

- TSDF 场景范围、截断和作者初始网格未逐项对照。官方有界提取器使用
  `depth_trunc=2*estimated_radius`、`voxel_size=depth_trunc/256`、`sdf_trunc=5*voxel_size`。
  本轮实际值依次为 3.7446445918、
  0.01462751794、0.07313758968。
- 论文式 (10) 的顶点邻域位移正则与发布代码的边端点位移差均方不同；正文的面积排名
  与表 6 的中位数倍数阈值也不完全一致。本轮没有将公式改写为另一算法。
- UV 重建保留 500、2000、4000、6000 步；顶点学习率衰减步数保留代码的 10000，实际训练 8000 步。
- 相机保留代码的居中投影，深度保留插值顶点距离。当前 COLMAP 输入为 1554×1162，
  缩放为 800×600 并同步缩放内参；尚未证明与作者论文实验输入逐像素相同。
- 固定状态的渲染、五项损失、梯度和一次 Adam 更新与原版对照通过，但还没有在完全相同
  输入、初始网格和随机状态下完成原版与 MeshSuite 的 8000 步训练轨迹对照。

## scan24 实测

**白背景修正后 CD 为 0.7313360 mm，仍未复现论文的 0.44 mm。**
两轮完整流程的差异同时涉及 2DGS 输入/初始化与 ExMesh 背景，不能据此区分哪个阶段导致指标变化。

| 指标 | 当前白背景流程 | 归档的旧黑背景设置 |
| --- | ---: | ---: |
| 初始粗网格 CD | 1.2039180 mm | 1.2731316 mm |
| 最终 accuracy | 0.9634353 mm | 0.7047252 mm |
| 最终 completeness | 0.4992367 mm | 0.4825949 mm |
| 最终 CD | 0.7313360 mm | 0.5936601 mm |
| PSNR / SSIM / LPIPS | 23.3234 / 0.9020 / 0.1135 | 23.8258 / 0.9068 / 0.1042 |
| 最终顶点 / 三角面 | 101739 / 202494 | 103142 / 205260 |

图像指标是全部 49 个训练视图的拟合指标，不是留出测试指标。CD 返回 `dtu_official`，
使用 mask 裁剪、尺度转换、ObsMask、Plane 和 DTU 真值点云，单位为 mm。
此前 PGSR / 10000 步测得的 0.4413 mm 也不属于本轮配置，不能替代本轮结果。

当前 2DGS 训练/提取耗时为 359.91 / 5.89 秒；
ExMesh 训练耗时 382.36 秒，进程内峰值 CUDA allocated 为
1321.93 MiB。初始化期间曾同时运行回归测试，不作严格速度比较。
最终模型独占 GPU、5 次预热/100 次计时为 4.724 ms / 211.66 FPS，
渲染峰值 CUDA allocated 为 0.2944 GiB，推理快照为
113.55 MiB。全设备 nvidia-smi 采样不是单模型显存。

## 验证与证据

- ExMesh 11 项测试通过，含透明/半透明/不透明像素合成、真实 CUDA 训练、黑/白背景
  跨拓扑更新的断点恢复、检查点背景保存和实际渲染背景。
- 完整回归 450 通过、5 跳过、5 失败；失败仍是既有 2DTS 测试引用缺失的
  `configs/opaque_2dts_mipnerf360/2dts/mipnerf360` 配置。
- 15 个场景配置都检查了白背景、alpha、主要权重及输出隔离；完整训练仅 scan24。
- 白背景初始化缓存复用检查通过；最终推理快照模型与 8000 步可恢复检查点模型逐项相同。
- OBJ 顶点、面及独立 UV 索引等于检查点，PNG 仅有最多半个 8-bit 色阶的量化误差。
- 标准入口完整运行与重复执行均以 0 退出；语法、静态错误和补丁空白检查通过。
- 旧黑背景网格的作者原版裁剪对照为 0.5935638 mm，与原测接近；距离计算仍用 MeshSuite
  官方式实现，这不等于整套作者评测器的独立复跑。
